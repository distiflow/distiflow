Start from what the user sees and does.
- Write each journey as screens and states: empty, loading, error, success, and partial data.
- Note what the user must understand at each step and what they can undo.
- Look at the current screens before proposing new ones; keep existing patterns.
- Include keyboard use, screen readers, small screens and slow networks.
Why: visual and interaction problems are cheapest to fix before any component exists.
